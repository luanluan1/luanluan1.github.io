模型训练的术语容易被逐个记住，却没有连成一条流程。这篇笔记从“是否需要微调”开始，把数据、训练循环和参数高效微调放在同一张图里理解。

## 先区分 RAG、结构化输出和微调

- 知识经常变化、回答需要引用文档：优先 RAG。
- 只是要求稳定 JSON：先使用模型的结构化输出、Schema 校验和重试。
- 需要模型稳定学会一种行为、风格或领域映射，且有足够高质量样本：再考虑微调。

微调不是给模型上传一份会频繁更新的公司制度。它更适合改变模型“怎么做”，RAG 更适合提供“现在知道什么”。

## 训练集、验证集和测试集

| 数据集 | 用途 | 什么时候看 |
| --- | --- | --- |
| 训练集 | 计算 Loss 和梯度，更新可训练参数 | 每个训练步骤 |
| 验证集 | 选择超参数、判断过拟合、选择检查点 | 训练过程中定期评估 |
| 测试集 | 对最终方案做一次尽量无偏的评估 | 方案确定后 |

验证集不是人工随便问几个问题。它是一组不参与参数更新的固定样本，用于比较学习率、训练轮数和 LoRA 秩等方案。

如果不断根据测试集结果调参数，测试集事实上就变成了验证集，最终分数会被“调高”，无法代表真实泛化能力。

## Loss、梯度和学习率

`Loss` 是模型输出与训练目标之间的误差度量。反向传播会计算每个可训练参数对 Loss 的影响方向和大小，这个量叫梯度。优化器再根据梯度更新参数。

```text
输入 -> 前向计算 -> Loss
                  -> 反向传播得到梯度
                  -> 优化器更新参数
```

学习率控制每次沿梯度方向走多远：

- 太小：收敛慢，有限训练时间内可能还没学到。
- 太大：容易越过较好的位置，Loss 震荡甚至发散，也可能出现梯度爆炸。
- 梯度消失通常与网络结构、激活和长链路传播有关，不是“学习率大”的同义词。

## Epoch、Batch 和 Batch Size

`Epoch` 表示完整遍历一遍训练集。`Batch` 是一次前向和反向计算使用的一组样本，`batch_size` 是其中样本数量。

假设训练集有 1,000 条数据，`batch_size=10`，那么一个 Epoch 大约有 100 个训练步骤。

Batch 太大可能爆显存，也可能改变优化特性；太小会让梯度噪声更大，并且不能充分利用硬件并行。它不是单纯的“越大越快”。

## 梯度累积是在多个小 Batch 后再更新

显存只能放下 `batch_size=8`，但希望接近 Batch 32 的更新效果，可以连续计算 4 个小 Batch，把梯度先累加起来，最后再执行一次优化器更新：

```text
8 条 -> 计算梯度 --\
8 条 -> 计算梯度 ---+
8 条 -> 计算梯度 ---+-> 一次参数更新
8 条 -> 计算梯度 --/
```

此时有效 Batch Size 约为：

```text
micro_batch_size × accumulation_steps × GPU 数量
8 × 4 × 1 = 32
```

它降低的是单次需要保存的激活显存，不会免掉四次前向和反向计算，因此训练时间仍然存在。

## LoRA 只训练一个低秩增量

完整微调会更新基础模型的大量权重。LoRA 冻结原权重矩阵 `W`，训练两个更小的矩阵 `A` 和 `B`，用它们的乘积表示权重增量：

```text
W' = W + B × A
```

如果 `W` 很大，而中间的秩 `r` 很小，`A` 和 `B` 的参数量就远少于直接训练 `W`。训练时梯度只更新 LoRA 参数，部署时可以单独加载适配器，也可以在需要时合并到基础权重。

低秩是一种假设：完成当前任务所需的权重变化，可以用较低维度表达。`r` 太小可能学不够，太大则增加显存、计算和过拟合风险。

## QLoRA 是量化基础模型加 LoRA

量化是用更少的比特近似表示权重。FP16 每个权重大约 2 字节，4-bit 每个权重理论上约 0.5 字节。

以 7B 模型的基础权重粗略估算：

```text
FP16: 7B × 2 字节   ≈ 14 GB
4-bit: 7B × 0.5 字节 ≈ 3.5 GB
```

QLoRA 通常把冻结的基础模型量化为 4-bit，LoRA 参数仍使用 BF16 或 FP16 训练。计算时框架会按需要把量化权重还原到适合矩阵计算的精度，但不会更新基础权重，梯度仍然只进入 LoRA 适配器。

`3.5 GB` 只是在估算基础权重。实际训练还需要量化元数据、激活值、LoRA 参数、梯度和框架工作区，所以显存占用会更高。

## 如何判断过拟合

典型信号是训练 Loss 继续下降，但验证集 Loss 开始上升，或者验证任务指标持续下降。此时可以：

- 选择验证表现最好的检查点，而不是最后一个检查点。
- 使用 Early Stopping，在验证指标长期不再改善时停止。
- 增加高质量数据、减少重复样本或降低训练轮数。
- 调整学习率、LoRA 秩、Dropout 等超参数。

最后只在测试集上评估选定方案。这样得到的结果才更接近模型面对新数据时的表现。

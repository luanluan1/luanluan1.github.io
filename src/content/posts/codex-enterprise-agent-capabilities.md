> [系列总览与完整目录](/posts/codex-enterprise-agent-control-plane/)

工作台和任务链路稳定到可以继续扩展以后，需求转向能力复用。员工希望保存常用报告规则，管理员希望添加工具，再把允许范围分发给组织；员工也需要组合自己的助手。

当前能力中心由内部 Skill 目录、MCP 管理、组织 Agent 模板和个人 Agent 构成。它们复用原来的任务、审批和文件交付，没有另建运行时。

## 几种能力分别保存什么

| 对象 | 保存的内容 | 当前使用方式 |
| --- | --- | --- |
| Skill | 工作说明、元数据、版本与哈希 | 作为有明确版本的上下文参考 |
| MCP 服务 | 端点、认证方式、发现结果与分发状态 | 提供可由 Agent 请求调用的工具 |
| 组织 Agent | 工作要求、任务类型、工具与 Skill 选择 | 管理员维护，可直接选用或复制 |
| 个人 Agent | 本人的工作要求及允许范围内的组合 | 仅本人查看和修改，新会话固定配置 |
| 连接凭据 | 控制面使用的服务认证数据 | 不交给模型，不作为 Skill 内容 |

当前没有公开市场、社区评分、任意 Git 安装或独立连接器管理平台。界面里的“内部市场”需求，先落实为可浏览、上传、下载和使用的企业内目录。

## Skill 发布后怎样进入任务

可执行成员上传单个 UTF-8 `SKILL.md`，填写标识、名称和变更说明。服务检查编码、大小、组织归属和内容哈希，通过后直接发布。用户明确要求 Skill 不走管理员审核，这项产品规则在实现中保留。

作者追加 v2 时生成新记录，不能覆盖 v1。同组织成员可以浏览和下载，跨组织不能读取；仅查看成员能够浏览下载，但不能发布或运行。下载到外部的副本已经脱离平台控制，停用目录不能收回它。

Agent 或新对话选择明确版本。任务保存版本和内容快照，Runner 在加载前检查编码与哈希，把 Skill 作为不可信工作参考加入输入；Agent 的工作要求则沿现有配置通道传入。

这一区分影响权限。Skill 说“请调用写入工具”，不能为任务增加工具、网络或凭据。是否可调用仍由组织分发、Agent 绑定、成员资格和实际运行规则决定。

单个 Skill 最多 256 KiB，组合最多 5 个且合计受限。普通停用阻止新任务及已有会话的下一轮，已经进入当前模型上下文的文字不能直接收回。当前没有额外实现 Skill 紧急撤权产品流程。

## MCP 从内置服务走向通用 HTTPS

第一版登记的是部署内置的本地测试记录 MCP，用真实初始化、发现和调用先验证标准契约。后续扩展为多个公共 HTTPS Streamable HTTP 服务，认证支持无认证或 Bearer。

管理员登记服务以后，先测试连接并发现工具，再明确勾选和保存组织分发。发现结果并不等于授权。成员不能自行填写任意服务端点或启动命令，只能在已分发工具中选择。

不同服务可能提供同名工具。平台按服务身份与远程名称生成内部工具 ID，再保留远程原名用于实际调用，避免跨服务误用权限。

工具参数依据发现的 JSON Schema 校验，并限制大小、深度和引用范围。当前支持有界对象及无环本地引用，不支持任意复杂 Schema 或必须使用 MCP tasks 的工具。拒绝不兼容契约时，不能假装已经发现成功。

```mermaid
flowchart LR
    A[管理员登记] --> T[连接测试与发现]
    T --> D[显式分发组织工具]
    D --> P[成员组合个人 Agent]
    P --> S[任务冻结工具定义]
    S --> Q[调用参数校验与审批]
    Q --> E[派发前实时授权复核]
    E --> R[执行结果或待核实]
```

## 连接测试为什么也需要边界

管理员能够输入 HTTPS 地址，并不意味着控制面应该对任意内部目标发请求。连接先检查协议与域名，再核对 DNS 返回的全部候选地址，拒绝回环、内网和保留地址。

实际连接固定到已经检查的地址，继续验证 TLS，并拒绝重定向。这样避免只校验一次域名文本，随后实际请求却去了另一个目标。响应体积、发现页数和总时限也受到限制。

当前每组织最多登记 20 个 MCP 服务，每服务最多发现 32 个工具、8 页结果。连接或发现清单变化会撤销分发，要求重新授权；连接测试在网络等待期间不占用全局治理锁，完成后再核对版本，防止迟到结果覆盖管理员刚做的停用。

## Bearer 怎样保存和更新

凭据由实例私有目录中的密钥进行 AES-GCM 加密，密文绑定组织与服务。浏览器保存后只显示是否配置，审计、任务快照和容器都不包含真实 Token。

同一端点编辑时，可以明确保留已有凭据；更换端点必须重新输入，不能把原 Token 静默发到新服务。备份需要同时保留数据库和实例私有密钥，只保存密文不足以恢复连接。

远程返回值还可能反射凭据。传输测试包含服务把 Token 放回元数据或结果的情况，平台拒绝或脱敏处理，错误只返回受控分类。

## 远程调用如何避免自动重放

当前所有第三方工具都进入人工审批，不采信服务的只读注解来直接豁免。批准以后，执行入口先持久化一次 `executing` 占用，再在真正派发前检查成员、Agent、工具、期限和运行状态。

网络调用放在数据库事务之外。期间撤权可能先发生，因此连接建立之后、工具请求发出之前还有一次即时复核。授权检查本身超过期限，也不能在稍后恢复时迟到派发。

远端收到请求后断开连接，平台不能判断它是否已经写入。此时工具和所属任务进入 `outcome_unknown`，保留待核实事实，不自动重试，也不创建另一个 Run 来重放。

如果进程在占用后、结果保存前消失，执行期限到达后同样按未知处理。重复执行只返回已有状态。它防止平台自动重复派发，严格的外部业务单次写入仍需要对方的幂等或事务支持。

## 个人 Agent 复用已有配置模型

个人 Agent 在已有配置上增加归属与模板来源。组织模板没有个人 owner，个人配置绑定成员；复制保存来源模板和版本，后续模板变化不会覆盖个人编辑。

保存使用版本校验和幂等键，冲突保留草稿。启用时核对所选能力仍可用，工具撤权继续影响实际执行。每人每组织最多 20 个个人 Agent，停用项也计入上限；它沿用部署提供的模型，没有个人密钥或任意模型切换。

隐私检查还补过一处返回边界。审批人需要查看具体工具参数和结果，不能因此从审批接口拿到个人 Agent 的完整工作要求和 Skill 内容。数据库继续保留内部快照，HTTP 返回只展示请求所需信息。

## 完整链路怎样验证

集成验证使用真实 TLS 测试服务、PostgreSQL 和浏览器，管理员完成登记与分发，成员组合个人 Agent，再由固定 Codex 发起动态工具请求。免费 provider 触发审批与实际 HTTPS 调用，最后生成报告产物。

故障测试包含并发仅派发一次、连接过程中撤权零写入、结果丢失不重放，以及他人和跨组织无法读取个人配置。真实企业 MCP 尚未指定，因此通用协议验证不能扩大为任意供应商兼容。

OAuth、内网端点、自签证书和任意 stdio 命令仍不开放。先把这些边界写明，才能判断下一家具体服务需要补的是认证、网络还是工具契约。
